# MODEL_NOTES — Sycamore valuation scaffolds

> **Read this first.** These workbooks are **rebuildable skeletons**, seeded from
> a live pull (`build-models <TICKER>`). They are **NOT** finished models and
> **must not be presented in an interview as autogenerated** (CLAUDE.md
> non-goal). The point is for *you* to rebuild each formula by hand and
> internalize it. This file gives you everything needed to do that from scratch.

## 0. What gets generated, and how

`python -m sycamore_prep.cli build-models <TICKER>` writes
`models/<TICKER>_model.xlsx` (gitignored — it contains real pulled data). The
generator (`src/sycamore_prep/models/builder.py`) calls the Phase-3/4 engines and
**seeds input cells with the real values, then writes LIVE Excel formulas** that
mirror the engine math — it never re-implements the math in Python and dumps
static numbers. So you can flex any driver in Excel and the valuation reflows.

- Valuation numbers come from `comps.run_comps()` (`CompsResult`).
- `shares` / `net_debt` / tangible book are read from the **same cached
  `FinancialsFrame`** the DCF used (`comps._last_shares`, `metrics.net_debt_fy`,
  `metrics.tangible_book_value_fy`), so the workbook ties to the `comps` CLI.
- The SOTP SpinCo leg is seeded from `spinoffs.run_track()` (`SpinoffRecord`).

Workbook tabs: **Inputs & Sources** · **DCF & Reverse-DCF** (or **Bank
Valuation** for banks) · **Normalized Earnings** · **Football Field** ·
**Spin-off SOTP** (only with `--spinco`) · **Notes**.

### Cell-type legend (the audit trail)
Every value cell is colour-tagged so you can see what is verified vs. a judgment
call (CLAUDE.md #3/#4):

| Colour | Meaning |
|---|---|
| amber | **input** — editable raw input |
| green | **formula** — computed in-sheet; do not overtype |
| blue | **EDGAR primary** — SEC XBRL, verified |
| orange | **yfinance (non-primary)** — convenience data, unverified |
| italic | **analyst assumption** — a judgment call |
| deep-orange / red | **downside anchor** — bear case, surfaced most prominently |

Drivers are exposed as **named ranges** (e.g. `=WACC`, `=NET_DEBT`) so formulas
read by name, not by cell address.

## 1. Inputs & Sources — line-item provenance

| Driver (named range) | Source | XBRL concept / origin |
|---|---|---|
| `WACC`, `TERM_G`, `YEARS`, `TAX` | assumption | `config.valuation.*`; tax = `normalized.DEFAULT_TAX_RATE` (0.21) |
| `WACC_STRESS` (1%), `TG_STRESS` (0.5%) | assumption | `reverse_dcf.build_cases` bear-stress defaults |
| `PRICE`, `MKT_CAP` | **yfinance (non-primary)** | quote; market cap (falls back to price × EDGAR shares) |
| `SHARES` | **EDGAR primary** | `WeightedAverageSharesDiluted` → `SharesOutstanding` |
| `NET_DEBT` | **EDGAR primary** | `LongTermDebt + ShortTermDebt − CashAndEquivalents` (NaN→0) |
| `FCFF0_BASE/BEAR/BULL` | **EDGAR primary** | FCF = `OperatingCashFlow − CapEx`: latest / min(last 5) / max(latest, mean last 5) |
| `ASSUMED_G` | assumption | franchise FCF CAGR, clipped to `min(10%, WACC−2%)`, floored at `TERM_G` |
| `IMPLIED_G_*` | seed | `reverse_dcf.solve_implied_growth` (bisection) — see §2 |
| `REVENUE`, `MEAN_OPM`, `TROUGH_OPM`, `INT_EXP` | **EDGAR primary** | `Revenues`, 5y mean/min `OperatingIncomeLoss/Revenues`, `InterestExpense` |
| `TBV_PS` (bank) | **EDGAR primary** | `(StockholdersEquity − Goodwill − IntangibleAssetsNet) / shares` |
| `PE_*`, `PTBV_*`, `PEER_PE_*` | derived | own-history band quartiles / peer-set P/E min·median·max |

## 2. DCF & Reverse-DCF (non-bank)

**Method:** FCFF, **end-of-year** discounting (conservative — demands a higher
implied growth to justify today's price), Gordon terminal value. Three cases
**Bear · Base · Bull**, bear first.

Per-case drivers are formulas off the shared named ranges, so flexing one driver
reflows all three columns:
- Bear WACC `=WACC+WACC_STRESS`, TG `=MAX(TERM_G-TG_STRESS,0)`, FCFF₀ `=FCFF0_BEAR`
- Base `=WACC` / `=TERM_G` / `=FCFF0_BASE`
- Bull WACC `=MAX(WACC-WACC_STRESS,TERM_G+TG_STRESS+0.005)`, TG `=TERM_G+TG_STRESS`, FCFF₀ `=FCFF0_BULL`

**Forward fair value** (fully live; mirrors `reverse_dcf.dcf_enterprise_value` /
`dcf_equity_value_per_share`):
- Year-*t* PV (per case column *c*, year in col A): `=IF($A12<=YEARS, c$7*(1+ASSUMED_G)^$A12/(1+c$5)^$A12, 0)`
- PV of terminal value: `=IF(c$5>c$6, c$7*(1+ASSUMED_G)^YEARS*(1+c$6)/(c$5-c$6)/(1+c$5)^YEARS, NA())`
- Enterprise value = Σ explicit PV + PV(TV); Equity = `EV − NET_DEBT`
- **Fair value/share** `=(Equity)/SHARES`; **Margin of safety** `=FairValue/PRICE-1`

To rebuild: lay out years 1..N, compound FCFF₀ at the assumed growth, discount at
the case WACC, add the discounted Gordon tail, subtract net debt, divide by
shares.

### Reverse read — implied growth + tie-out (why it ties to `comps`)
The reverse solve (what near-term FCFF growth today's price implies) is a
**bisection** (`solve_implied_growth`) — there is no clean closed-form Excel
formula for it. So the workbook:
1. **Seeds** `IMPLIED_G_*` from the engine's solver, and
2. adds an Excel **CHECK**: `EV @ implied growth` computed with the
   growing-annuity closed form
   `FCFF₀·x·(1−xⁿ)/(1−x) + FCFF₀·(1+g)ⁿ·(1+tg)/(wacc−tg)/(1+wacc)ⁿ`,
   where `x=(1+g)/(1+wacc)` — algebraically identical to the per-year loop —
   minus `Current EV = MKT_CAP + NET_DEBT`.

On open the **tie-out residual ≈ 0** (cell turns green), which is the visual
proof the Excel reverse-DCF matches the `comps <TICKER>` CLI implied-growth
number. **After flexing** WACC/TG/FCFF₀, re-solve: *Data ▸ What-If ▸ Goal Seek —
Set the residual cell To 0 By changing the matching `IMPLIED_G_*` input.*

## 3. Normalized / mid-cycle earnings (`comps.normalized`)
De-noises a cyclically distorted trailing P/E. Two columns, **Trough (downside)
first**, then Mid-cycle:
- Operating income `=TROUGH_OPM*REVENUE` / `=MEAN_OPM*REVENUE`
- Net income after tax `=(margin*REVENUE − INT_EXP)*(1−TAX)` (interest before tax
  so a levered name isn't flattered)
- EPS `= NI / SHARES`; P/E `= PRICE / EPS`
- **Trough P/E** is the explicit downside anchor (red). Trailing P/E (from
  as-reported `EpsDiluted`) is seeded as a reference only.

## 4. Football Field (relative value)
Each method is a valuation **range** (Low/Mid/High), bear column first, with
in-cell data bars and a current-price marker. Methods:
- **Reverse DCF** — bear/base/bull fair values (`=FV_BEAR/FV_BASE/FV_BULL`).
- **Own-history P/E** — `TROUGH_EPS×PE_P25` / `NORM_EPS×PE_MEDIAN` / `NORM_EPS×PE_P75`.
- **Peer P/E** — `NORM_EPS ×` peer P/E min·median·max.
- (Banks) **Own-history P/TBV** — `TBV_PS ×` P/TBV quartiles.

A true floating-bar chart is a **deliberate non-goal** (lean ethos). To add one:
build a stacked `BarChart`, set the first ("base") series = the Low column with
no fill, and the second = (High−Low); category axis = method labels.

## 5. Bank variant (`metrics.is_bank` → `Deposits` tag)
Banks get **no FCFF DCF and no SOTP** (not meaningful) — those tabs are omitted.
The **Bank Valuation** tab values the bank two ways, downside column first:
- **P/TBV:** `Fair value = PTBV_TARGET × TBV_PS` (downside uses the p25 multiple).
- **Normalized P/E:** `Fair value = NORM_PE_TARGET × NORM_EPS` (downside uses
  `TROUGH_EPS`).
Football field uses **P/E + P/TBV** bands only.

## 6. Spin-off SOTP / stub (`spinoffs.run_track`)
The tracker provides only the SpinCo's **FCF** and **ratios** (`net_debt_ebitda`,
`roic`, `fcf_margin`, `distribution_ratio`) — **not** absolute segment EBITDA,
revenue, share count, or a segment split. So:
- **Parent ex-SpinCo legs are ANALYST INPUTS** — enter each segment's EBITDA and
  an EV/EBITDA multiple (from the Form 10 / peers); part EV `= EBITDA × multiple`.
- **SpinCo leg is seeded** — SpinCo FCF is filled from the tracker; you supply a
  P/FCF multiple → SpinCo equity `= FCF × P/FCF`.
- Consolidated: Σ parent segment EV − `NET_DEBT` → `÷ SHARES` → implied
  value/share → MoS vs price. Tracker **downside flags** (e.g.
  `forced_selling_window`) are surfaced at the bottom.
This tab is emitted only with `--spinco`.

## 7. Rebuilding from scratch
1. Pull the data: `pull-fundamentals <TICKER>`, then `comps <TICKER>` (and
   `spinoffs track <PARENT> --spinco <SPINCO>` if relevant) to see the engine
   numbers.
2. Re-enter the drivers on **Inputs & Sources** by hand from the EDGAR filings.
3. Re-derive every green cell using the formulas in §2–§6. Do **not** copy the
   generated file into a pitch — own the logic.

## 8. Caveats
- **openpyxl writes formula strings; it does not compute them.** Always open the
  file in Excel and confirm: no `#REF!`/`#DIV/0!`/`#NAME?`; the reverse-DCF
  residual ≈ 0 (and matches `comps`); the bear column flexes when you change
  `WACC`. (The test suite asserts the formula *strings* and proves the
  *arithmetic* matches the engine — it cannot prove evaluation.)
- `YEARS` materializes a fixed number of PV rows at write time; shortening
  `YEARS` zeroes the tail via the per-row `IF`, but **lengthening** it beyond the
  generated rows requires extending the strip by hand.
- Prices are unadjusted FY-end closes; own-history bands need ≥3 annual
  observations; a split inside the lookback would distort a band.
- `models/<TICKER>_model.xlsx` is gitignored (real data). The committed
  `models/templates/example_synthetic_model.xlsx` is built from **synthetic**
  numbers (`scripts/make_example_model.py`) purely to show the layout.
