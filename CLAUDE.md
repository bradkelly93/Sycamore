# CLAUDE.md — Sycamore Interview Prep Toolkit

This file is the durable operating contract for any agent working in this repo.
Read it before writing code.

## What this toolkit is

A decision-support toolkit for preparing a bottom-up, fundamental value stock
pitch and modeling exercise for a Research Analyst interview at Sycamore
Capital (Victory Capital mid/small-cap value franchise, Cincinnati). It is
analyst tooling, not a quant black box.

## Operating philosophy (do not deviate)

1. **Downside first.** Sycamore's first principle is limiting permanent loss
   of capital. Every screen, score, and model output must surface downside /
   margin-of-safety metrics at least as prominently as upside.
2. **The three-attribute frame.** Sycamore screens for (a) a better business
   with above-average financial strength, (b) an exploitable valuation
   disparity vs. estimated fair value, (c) the prospect of improving
   fundamentals. Every screener score and comp output must decompose into
   these three axes — never collapse them into one opaque number.
3. **Primary-source discipline.** Default to SEC filings (EDGAR XBRL) for
   fundamentals. Anything from a non-primary feed — yfinance prices/market cap,
   tastytrade option-implied volatility, a TradingView technical screen, or
   Polymarket implied probabilities — must be tagged `source="… (non-primary)"`
   so the analyst sees what is verified vs. convenience/market-opinion data.
   (Option-implied vol is "primary for vol" in that the options venue *is* the
   source, but it is still non-primary vs. the fundamental thesis and never
   feeds it.) Never splice a metric from one source with a related metric from
   another without labeling both.
4. **Auditable, not magic.** Every computed number must be traceable to its
   source line item and formula. No hidden heuristics. Outputs include a
   `source` column.
5. **Swappable data layer.** All data access goes through the adapter
   interfaces in `src/sycamore_prep/adapters/base.py`. A future FactSet or
   Bloomberg provider must drop in without touching downstream code.
6. **No gold-plating.** CLI + Excel/CSV outputs only. No web UI, no database
   server, no auth, unless explicitly requested later.

## Non-primary overlays (decision-support lenses — never scoring)

The fundamental engine (universe → screener → comps → reverse DCF → spin-offs →
Excel models) is the core and stays strictly bottom-up. Three optional,
**read-only, NON-PRIMARY** overlays may surface market context beside that core
for the analyst to interpret. They share one hard rule: **they are structurally
walled off from the three-attribute score, the composite, the rank, and every
fair-value path** — spliced in only after scoring is final, as extra
source-tagged columns to the right of the downside flags.

- **Volatility (`adapters/tastytrade_*`, `metrics/volatility.py`, `vol` CLI).**
  Option-implied vol as a downside cross-check (IV rank/percentile, expected
  move, 25-delta put skew). DATA-ONLY: reads market-level metrics for names
  under research — never positions, never orders. Auth (OAuth2) via env, never
  committed.
- **Technical (`adapters/tradingview.py` + `trend_regime.py` + `csv_screen.py`,
  `screen --tv-overlay`).** A Bull/Neutral/Bear regime or saved TradingView
  screen as context; `tv_divergence` is an interpretive prompt, not a signal.
- **Prediction markets (`prediction_markets/`, Polymarket).** Company/peer/
  industry/macro event-risk implied probabilities. No prediction-market
  *trading*.

## Explicit non-goals

- Not a backtester, portfolio optimizer, or order-placement / live-trading
  tool. The vol overlay reads option-implied metrics but **never** trades or
  reads positions; macro/thematic and technical inputs **never** drive the
  screener score, comps, or fair value.
- The Excel models in `models/` are scaffolds for the owner to rebuild and
  internalize. Do not present them in an interview as autogenerated.

## Code conventions

- Python 3.11+. Pin versions in `pyproject.toml`.
- All adapters return a tidy DataFrame with a `source` column.
- Cache every primary-source pull to `data/cache/` as parquet keyed by
  `ticker + concept + period` so runs are reproducible and offline-replayable.
- Respect SEC rate limits (~10 req/s) and always send the configured
  `User-Agent` header. The User-Agent string lives in `config.yaml`.
- Tests live under `tests/` and cover metric calculations against
  hand-computed fixtures.
- CLI lives in `src/sycamore_prep/cli.py` (typer). Every command must be
  documented in `README.md` with an example invocation.

## Repo map

```
src/sycamore_prep/
  adapters/      # base.py interfaces + impls: Fundamentals (EDGAR), Price
                 #   (yfinance), Filings (EDGAR submissions/FTS), Volatility
                 #   (tastytrade + dxLink stream), TechnicalScreen (TradingView
                 #   / trend-regime / csv), EventProbability (Polymarket)

                 #   volatility (overlay), trend (overlay)
  universe/      # builder.py — IWS/IWN + Sycamore overlay
  screener/      # three-attribute quality-value screen (+ non-scoring overlays)
  comps/         # comps + normalized earnings + reverse DCF
  spinoffs/      # 10-12B / Form 10 tracker
  models/        # Excel model-scaffold generator (build-models)
  pipeline.py    # one-funnel orchestrator: universe→screen→comps+model→dossiers
  prediction_markets/  # NON-PRIMARY Polymarket overlay: discover + event-risk
                 #   lens (company/peer/industry/macro). Walled off from scoring.
models/          # Excel scaffolds + MODEL_NOTES.md (committed: notes + templates)
data/raw/        # manually-dropped CSVs (ETF / fund holdings)
data/cache/      # parquet cache of pulled fundamentals + prices + overlays
```

## Build phases

The core fundamental engine was built in order (1→5); the overlays + the
orchestrator layer on top without touching the scoring path.

1. Data + universe — adapters, cache, universe builder.
2. Screener — metrics + three-attribute screen.
3. Comps + normalized earnings + reverse DCF.
4. Spin-off tracker.
5. Excel model scaffolds + MODEL_NOTES.md (`build-models`).
6. Pipeline — one-funnel orchestrator (universe → screen → shortlist →
   comps + model per name → ranked dossier index).
7. Prediction-market overlay — Polymarket adapter + discovery + event-risk lens.

NON-PRIMARY, read-only overlays (any order; never feed the composite/rank):
volatility (tastytrade), technical (TradingView / trend-regime), and the
prediction-market lens above.
